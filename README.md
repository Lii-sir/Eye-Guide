# EyeGuide

EyeGuide 是一个面向盲人辅助出行的电脑端原型。它把三个关键能力先串起来：

- 自由探索模式：打开摄像头，实时检测前方障碍并语音播报。
- 路线导航模式：先获取步行路线，再结合摄像头感知做导航提示。
- 模拟测试模式：读取本地视频，回放并验证整套感知与播报流程。
- GPS 定位接入：支持电脑端 USB/NMEA GPS，把实时坐标作为导航起点。

这版重点是先把“完整闭环”做出来，方便后续逐步替换成更强的检测模型、地图服务、GPS 定位和语音交互。

## 当前能力

- `Tkinter` 桌面控制面板
- `OpenCV` 视频采集与渲染
- `pyttsx3` 本地 TTS 语音播报
- `pyserial` 串口 GPS 接入
- `OSRM + Nominatim` 的在线步行路线获取
- `Ultralytics YOLO` 可选目标检测
- 无 YOLO 时使用 `OpenCV` 启发式规则兜底
- 风险去重、播报优先级和冷却时间控制
- 按 `domain / services / app / ui / core` 分层组织

## 使用 `uv`

1. 准备 `uv` 和 Python 3.10+
2. 安装依赖

```bash
uv sync
```

3. 启动程序

```bash
uv run eyeguide
```

如果你想启用 YOLO 目标检测，再安装可选依赖：

```bash
uv sync --extra yolo
```

## 使用说明

### 自由探索模式

- 点击“启动自由探索”
- 程序会打开默认摄像头
- 检测到前方人员、车辆、近距离障碍或疑似台阶时会自动播报

### 路线导航模式

- 输入起点和终点
- 如果已经连接 GPS，可以点击“用当前 GPS 位置填入起点”
- 点击“启动路线导航”
- 程序会在线获取步行路线
- 如果真实路线获取失败，程序会停止启动导航，不会回退到演示路线
- 打开摄像头后，屏幕上会显示当前导航指令
- 在视频窗口中按 `N` 可切换到下一条路线指令
- 按 `R` 可重复当前导航指令

### 模拟测试模式

- 先选择一段本地视频
- 点击“启动模拟测试”
- 程序会像实时摄像头一样处理视频并播报结果

### 快捷键

- `Q`：退出当前处理会话
- `N`：下一条导航指令
- `R`：重复当前导航指令

## GPS 使用说明

- 当前优先支持输出 `NMEA` 语句的 USB/串口 GPS 设备
- 在界面里先刷新串口列表，再选择对应 `COM` 口并连接
- 等待状态栏出现“GPS 已定位”后，可一键把当前位置写入导航起点
- 这版先解决“当前位置获取”，还没有做基于 GPS 的自动到点切换和偏航重规划
- 为了避免误导，路线服务失败时不会自动生成演示导航

## 检测策略说明

### 1. YOLO 可选增强

如果你通过 `uv sync --extra yolo` 安装了 `ultralytics`，程序会优先启用 YOLO 目标检测，用于识别：

- 行人
- 自行车/摩托车
- 汽车/公交车/卡车
- 椅子、长椅、箱包等路面障碍

### 2. OpenCV 启发式兜底

如果没有 YOLO，程序仍能运行，并使用一些轻量规则：

- `HOG` 行人检测
- 画面下半部的大轮廓障碍估计
- 底部多条水平边缘的“疑似台阶”提示

## 已知限制

- 这不是医疗或安全认证产品，不能直接作为正式盲人导航设备使用
- 单目摄像头下的距离判断目前只是近似估计
- “台阶/坑洼/路沿”检测仍是启发式，误报和漏报都可能存在
- 已支持 GPS 接入，但路线步骤仍默认靠手动推进，尚未实现自动路线跟踪
- 公共路线服务依赖网络，可用性受外部服务影响

## 下一步建议

优先建议按下面顺序继续升级：

1. 接入更强的多模态感知模型，用于识别台阶、路沿、坑洼、红绿灯和盲道。
2. 引入深度估计或双目/ToF 方案，提升距离判断可靠性。
3. 接入手机 GPS、IMU 和耳机播报，形成真正可移动的导航设备。
4. 加入语音唤醒和语音命令，例如“重复上一条”“暂停播报”“回家”。
5. 针对盲人出行场景重新设计告警策略，减少高频重复播报带来的疲劳。

## 工程结构说明

- `eyeguide/domain`：放数据模型，例如模式、路线、检测事件。
- `eyeguide/services`：放可替换的能力模块，例如导航、视觉、语音。
- `eyeguide/app`：放运行编排和会话控制，把业务流程从界面剥离出来。
- `eyeguide/ui`：放桌面端界面，只负责输入输出和事件绑定。
- `eyeguide/core`：放全局配置和应用事件。
