# EyeGuide V2 工程落地规划

> 日期：2026-10-23（Asia/Shanghai）
> 状态：建议架构基线；尚未实现或压测
> 配套文档：[从零重写架构](greenfield-rewrite-architecture-2026-10-12.md)
> 优先级：本规划细化数据库、部署和资源边界；与旧方案冲突时，以本规划为准。

## 1. 目标与默认决策

从空骨架实现 V2，保留 V1 作为行为和算法参考。目标是可安装、可部署、可回归、可诊断的辅助导航应用。

采用模块化单体，把实时感知链路和持久化业务链路分开。第一阶段支持本地运行与局域网试用；对公网开放、多账号和多机部署设独立交付门槛。数据库从架构设计开始纳入，不把复杂账户系统作为 Fake 垂直切片的前置依赖。

| 决策 | 默认方案 | 引入或升级条件 |
| --- | --- | --- |
| 桌面存储 | SQLite，本机文件，由应用独占管理 | 出现集中共享和多实例写入需求时采用服务端数据库 |
| 云端存储 | PostgreSQL，单独的数据服务 | 多用户试点阶段交付；不要求先完成 SQLite 到 PostgreSQL 的线上迁移 |
| 业务持久化 | Repository + UnitOfWork 端口，关系库适配器 | 不向领域层暴露数据库连接或 ORM 类型 |
| 模型资源 | 进程级 ModelRegistry + InferenceScheduler | 初始每设备并发 1；压测后调整 |
| 会话状态 | SessionRuntime 内存隔离 | 数据库只保存摘要，不恢复实时帧槽 |
| 部署 | 本地 Windows；服务端先单实例、单 API worker | 多机部署须另行实现会话归属和推理通信 |
| 文件资产 | 权重和获准采集的样本放文件目录，库中仅存元数据 | 多节点需共享资产时再接对象存储 |
| 消息基础设施 | 首版使用进程内有界队列 | 只有可靠异步投递或跨进程需求明确后再引入 |

以上是设计选择，不是当前代码已经具备的能力。SQLite 的定位参考其[官方适用场景](https://www.sqlite.org/whentouse.html)；数据库具体版本和驱动须在实现时通过支持矩阵与干净安装确定。

## 2. 总体边界与处理路径

~~~text
Desktop / Mobile Web
  → API / Desktop Controller
  → Application Services
      ├─ 实时：SessionRuntime → 有界帧槽 → InferenceScheduler → 模型 → 风险/播报策略
      │                                                     → FrameResult → 当前连接
      └─ 持久化：Settings / SessionSummary / Feedback → Repository + UnitOfWork
                                                       → SQLite / PostgreSQL

进程级：模型、推理调度器、连接池、配置、健康状态
会话级：owner、连接代次、导航状态、GPS/IMU、帧槽、冷却去重、取消信号
外部：地图服务、定位设备、浏览器/本机语音、资产目录
~~~

实时处理不逐帧读写关系库，不因统计写入失败而卡住风险结果。配置更新、权限变化等要求可靠保存的操作必须在事务提交后报告成功。

### 正常流程

1. 校验设备或用户身份、来源、会话配额和请求大小。
2. 创建会话并保留配置版本、模型版本；需持久化摘要的模式下先提交启动记录。
3. 接收帧，先限制编码体积，再限制解码尺寸；按会话替换待处理帧。
4. 调度器公平选择有效会话，调用模型，执行会话独立的风险与播报策略。
5. 校验连接代次、配置代次和结果有效期后返回；过期结果不得触发播报。
6. 统计通过有界缓冲写入摘要；结束时更新终态，释放会话资源。

### 故障流程

- 数据库不可用：现有实时会话继续；配置修改和必须持久化的新会话返回明确失败。纯本地临时模式可在启动前显式选择，不能自动假装保存成功。
- 非关键统计失败：有界重试，超过容量丢弃并计数；首版承认统计可能不完整，不宣称可靠投递。
- 模型加载失败：公开降级能力状态；可用模型继续，必需能力缺失时拒绝启动对应模式。
- 推理超时：结果标记无效；底层调用未结束前不释放并发名额。取消 asyncio task 不视为终止 GPU/线程调用。
- 强制退出：下次启动把遗留 active 摘要标为 interrupted；不从数据库复活导航和旧帧。

## 3. 数据分级与持久化边界

| 数据 | 保存位置 | 默认保留与语义 |
| --- | --- | --- |
| 当前图像、解码 buffer、逐帧框和深度 | 内存 | 处理结束释放，默认不保存 |
| 当前 GPS/IMU、导航进度、播报去重 | 会话内存 | 会话结束清理，不恢复旧定位 |
| 用户/设备偏好 | 关系库 | 显式保存；含 schema_version 和 revision |
| 会话摘要 | 关系库 | 起止时间、结束原因、计数、耗时聚合、配置/模型版本；默认不含位置 |
| 常用目的地、历史路线 | 后续可选关系表 | 首版关闭；有产品需求和用户选择后再交付 |
| 诊断事件 | 脱敏日志；少量结构化反馈入库 | 不默认复制所有感知事件；试点保留 7 天为建议值 |
| 用户提交的样本/反馈 | 文件目录 + 元数据 | 主动提交且用途明确；建议 30 天后清理，可配置 |
| 模型及配置版本 | 资产清单 + 关系库元数据 | 内容哈希、格式、输入规格、许可证、验证状态 |
| API Key、设备访问凭据 | 环境/操作系统凭据存储；凭据摘要入库 | 不进入普通设置 JSON、日志、响应或样本 |

保留期限是产品建议，尚非已执行规则。删除流程需覆盖数据库记录、样本文件、索引和备份到期；恢复备份时重新应用删除记录，防止已删数据重新进入服务。

## 4. 数据模型草案

所有 ID 由应用生成 UUID；持久化时间使用 UTC。SQLite 与 PostgreSQL 的时间/JSON 类型映射在 adapter 内明确测试。数值单位写入字段名或 schema；高频查询字段不埋在 JSON 中。

| 表 | 主要字段 | 约束与索引 |
| --- | --- | --- |
| devices | id, label, credential_digest, revoked_at, created_at | 凭据摘要唯一；撤销立即影响新连接 |
| profiles | id, kind, created_at, deleted_at | 本地单 profile；云端由登录身份映射，不能靠客户端随意选择 |
| device_bindings | profile_id, device_id, created_at | 联合唯一；所有权变更需授权事务 |
| settings | profile_id, schema_version, revision, payload, updated_at | profile_id 唯一；revision 做乐观锁 |
| sessions | id, profile_id, device_id, runtime_instance_id, state, started_at, ended_at, end_reason, config_snapshot, model_manifest_hash | 索引 (profile_id, started_at)；摘要状态不作为运行时真相 |
| session_summaries | session_id, frames_received, frames_processed, frames_dropped, errors, latency_histogram, updated_at | session_id 外键且唯一；指标更新幂等 |
| model_versions | id, name, version, sha256, asset_key, input_spec, license_ref, validation_state | (name, version) 唯一；sha256 校验资产 |
| feedback | id, profile_id, session_id, category, note, created_at | 所属关系校验；note 长度受限 |
| artifacts | id, feedback_id, storage_key, sha256, byte_size, expires_at, deletion_state | storage_key 唯一；不接受任意绝对路径 |

本地试点只需 profiles、settings、sessions、session_summaries；设备、反馈、资产和模型登记按阶段加入。账号采用后续 identity adapter，不在这里提前自建密码找回、社交登录等完整体系。

配置快照记录实际使用的脱敏参数，并给敏感字段做排除；更新配置仅影响允许即时生效的参数，其余返回 requires_restart。切换模型属于受控发布，不允许普通会话设置加载任意路径。

### 事务、幂等和查询

- settings 更新使用 expected_revision；冲突返回版本冲突，不覆盖别人刚保存的数据。
- 开始和结束会话各自短事务；结束请求携带 request_id，重复结束不重复累计摘要。
- 采用有限的幂等记录保留窗口，键包含 owner、operation、request_id；相同键但不同 payload 拒绝。
- 每个工作单元使用独立数据库 session，不跨线程共享 ORM session，不在数据库事务中等待模型或地图 HTTP。
- 历史会话采用分页与稳定排序；每次查询按认证 owner 过滤，并测试越权 ID 访问。
- 避免每帧更新一行摘要。按时间窗口聚合并写入绝对计数/序号，避免重试重复增加计数。

### Schema 演进

数据库 adapter 可采用 SQLAlchemy 与 Alembic，具体版本在实现时验证。迁移脚本独立发布；云端只允许一个迁移任务执行。SQLite 与 PostgreSQL 分别运行迁移和仓储契约测试，不能假定替换连接字符串就能迁移。

已有 SQLite 数据只有在确定上传意愿后，通过显式导出/导入工具迁移：校验 schema、单位、ID 冲突、行数和校验和；失败不切换旧库。首版可让两种部署独立建库，降低迁移范围。

## 5. 多会话和模型资源调度

当前每连接创建 SceneAnalyzer（eyeguide/api/session.py:81-85）。由此推断：保留这种资源所有权可能使多连接下的模型内存开销随连接数增长；实际权重加载和显存曲线尚未测量。

V2 建议把模型权重与会话策略状态分离：共享的是受控模型句柄，不能共享导航、去重、缓存来源帧或可变图像。若 adapter 内部存在跟踪器或跨帧缓存，必须提供每会话上下文，或禁用该共享实现。

- 每会话最多 1 个待处理帧；同时运行的推理数量受设备配额限制。
- 全局限制连接数、活跃会话数、待解码字节和推理任务数；满额返回 BUSY 和建议重试时间。
- 轮转选择有待处理帧的会话，防止单个高频客户端占满设备。
- 限速在解码前执行；限制 WebSocket 消息大小、图片像素数和发送队列容量。
- 发送慢的客户端丢弃旧实时结果；控制消息有界且超时断开，不能无限堆积。
- 请求标识包含 session_id、connection_generation、frame_id、config_revision；迟到结果不得写入新连接。
- 权重变更先加载并验证，确认显存可容纳；不够时采用维护窗口。失败保留上一个可用版本。
- 桌面默认本机 TTS；云端移动会话只向所属浏览器发送播报指令，不让服务端共享音箱播报所有用户内容。

初始单进程、单 API worker；模型重负载通过受控 worker 执行。推理长期无法返回时将实例置为不接收新会话并由进程管理器重启。后续若需要强隔离，再实现独立推理进程及有界 IPC、超时和故障恢复。

多 worker 是多进程部署方式，参见 [FastAPI 官方文档](https://fastapi.tiangolo.com/deployment/server-workers/)。本方案据此要求：扩容前重新核算模型副本、会话内存和连接路由；PostgreSQL 不会自动解决实时会话共享。

## 6. 部署与运维交付

| 形态 | 部署组成 | 数据与限制 |
| --- | --- | --- |
| 开发/Fake | Python API + Fake adapters + 临时存储 | 无模型和公网可运行 |
| 本地桌面 | Windows 应用、SQLite、外置权重 | 数据只在本机；有备份/导出入口 |
| 局域网试点 | 单主机 API、HTTPS、设备配对、SQLite | 单实例；容量以实测为准 |
| 多用户服务端 | HTTPS 入口、单 API 实例、PostgreSQL、持久卷 | 完成鉴权、配额、恢复演练后开放 |
| 后续扩容 | API 与推理部署拆分、会话路由 | 独立 ADR，不作为首轮前置工作 |

运行配置区分 dev/test/prod；镜像/安装包固定依赖与模型 manifest。Windows 桌面和 Linux 服务端分别验收，不假设现有 CUDA、Paddle 和系统语音依赖跨平台通用。

- /healthz：进程存活，避免数据库短故障引起无限重启。
- /readyz：必需模型、调度器和部署所需数据库可服务；可选深度/语音缺失以 degraded 展示。
- 公开健康接口只给最小状态；详细错误与资产路径仅管理端可见。
- 服务启动先校验配置、数据库 schema、模型哈希，再预热必需模型；完成前不接收业务会话。
- 停机先标记不就绪、停止接收会话，通知客户端，取消待处理帧，等待正在执行的任务，保存摘要，关闭资源。
- 发布应用版本与模型版本分别记录；先试点一台实例，确认后扩大。客户端重连创建新实时会话，不承诺无缝恢复旧导航。

### 备份、恢复和回滚

本地使用一致性备份机制，不能把正在写入的 SQLite 文件随意复制当成有效备份。云端按选择的 PostgreSQL 备份方式配置周期和保留；[官方文档](https://www.postgresql.org/docs/current/backup.html)列出 SQL dump、文件系统备份和连续归档，应按恢复目标选择。

试点建议目标：持久业务数据 RPO ≤24 小时、RTO ≤4 小时；实时帧与内存导航不在恢复范围。目标尚未通过演练证明。每次发布涉及 schema 变更时先备份，并在空实例恢复验证。应用优先回滚到兼容旧 schema 的版本；破坏性迁移采用先扩展再收缩，不能把自动降级数据库当作默认回滚办法。

## 7. 接口、安全与观测

保留现有 WebSocket 协议兼容层；设备配对、鉴权、会话归属属于新版本的显式能力。公开部署不得为了兼容旧客户端而跳过身份校验。

新增业务接口草案：读取/更新偏好、创建/结束会话、分页查询本人会话摘要、提交/删除反馈。URL 和 JSON schema 在实现前固化为契约；session_id 不是访问凭证。浏览器优先使用安全会话机制或一次性连接票据，避免把长期 token 放在 URL 和访问日志中。

日志字段：request_id、匿名化 session_id、operation、error_code、duration、release、model_version。默认排除图像、精确坐标、路线起终点、凭据和任意用户原始文本。指标标签只使用有限枚举，用户/会话 ID 不作为标签。

必须观测：活跃连接、推理排队、处理/丢弃帧数、结果年龄分布、阶段耗时、GPU/进程内存、数据库池等待、统计丢弃、关闭超时。失败日志关联指标，用户收到可理解的状态和恢复操作。

### 容量与性能验收草案

先冻结参考设备、模型组合、分辨率、上传 FPS、网络 RTT 和并发数，再测 1/2/4 客户端阶梯，不能先承诺支持人数。

- 保留当前 500ms 结果过期语义作为兼容基线；先区分服务端单调时钟耗时与客户端端到端耗时，不能直接相减不同设备时钟来证明延迟。
- 正常试点负载下，建议有效结果端到端 p95 ≤500ms；同时报告过期比例和有效输出 FPS，避免只统计成功快帧。
- 在 500ms 内有有效输出的窗口占比建议 ≥95%；具体采样窗口和最低有效 FPS 由回放与现场测试确定后冻结。
- 超载时内存队列保持有界，明确返回 BUSY，不以积压旧帧维持表面吞吐。
- 持续运行 2 小时并反复断连/启停，内存与显存达到稳定平台，无持续增长。
- 停止操作建议 5 秒内结束；超时返回 stopping/failed，不能报告释放成功。

上述均为待验证目标；普通 CI 不做依赖硬件的性能承诺。

## 8. 从零实现的交付顺序

沿用原方案的 Phase 0—8，增加以下工程交付门槛；持久化骨架在真实模型之前完成，公网能力在本地链路稳定后交付。

| 里程碑 | 具体交付 | 验收与失败处理 |
| --- | --- | --- |
| M0 冻结边界 | 行为/协议样例、资产 manifest、部署形态、ADR | 不移动权重；核对旧启动入口 |
| M1 Fake 闭环 | src 骨架、会话状态机、帧槽、Fake API、导入边界 | 无硬件运行；两会话隔离、断连、迟到结果测试 |
| M2 持久化骨架 | Repository/UoW、SQLite、首个 schema、设置与摘要 | 重启读回设置、乐观锁、磁盘错误、迁移测试；失败不伪报保存 |
| M3 真实感知 | ModelRegistry、调度器、YOLO/深度/盲道 adapter | 回放差异、显存曲线、公平性、过期结果不播报 |
| M4 导航与入口 | GPS、地图、语音、桌面、移动兼容层 | 坐标/单位、定位过期、EOF、权限拒绝、HTTPS 真机验收 |
| M5 局域网试点 | 设备配对、配额、可观测性、安装包、运行手册 | 越权/撤销、超载、停机、2 小时稳定性、SQLite 恢复演练 |
| M6 多用户部署 | PostgreSQL adapter、身份适配、反馈、备份任务 | 两种数据库仓储契约；空库升级/旧库升级；备份恢复与访问隔离 |
| M7 正式切换 | 支持矩阵、版本发布、回滚演练、V1 归档 | 无未解释行为漂移，恢复目标实测；再切正式入口 |

M1 和 M2 可以按用例逐项落地，无需先实现整个表模型。首个可评审实现应只包含：Fake 帧处理、两会话隔离、停止、SQLite 偏好保存和会话摘要，并提供一条可重复运行的启动命令及验收脚本。

### 需要验证的核心故障

1. 保存配置时断电/磁盘满，恢复后数据一致且错误可见。
2. 数据库中断不阻塞已有实时结果，业务保存明确失败。
3. 推理超时并断连，迟到结果不进入新会话，执行名额不提前复用。
4. 两客户端导航和语音不会串线，高频客户端不饿死低频客户端。
5. 重复结束/重试请求不重复累计会话计数。
6. 备份在空环境恢复后，可启动、可读取设置，旧 active 会话被标记为 interrupted。
7. 切回上个应用/模型版本后能启动；schema 不兼容时阻止错误回滚。
